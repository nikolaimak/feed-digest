🎯 Practical takeaways

  1. Preserve control state explicitly. Keep governing rules, accepted decisions and the current task state separate from disposable transcripts; test that compaction preserves them.
  2. Evaluate counterfactually. Run the same task with and without a retrieved skill or harness change, repeat it, and keep the environment fixed enough to attribute the result.
  3. Design long runs as distributed systems. Use durable state, idempotent steps, checkpoints, bounded retries and selective replanning rather than relying on one enormous conversation.
  4. Treat skills and tool descriptions as executable supply chain. Review provenance, scope credentials, pin packages and isolate the runtime before increasing autonomy.
  5. Move review towards evidence. When generated code is not routinely read, strengthen specifications, behavioural tests, security checks, observability and rollback.
  6. Standardise interfaces, not curiosity. Let teams explore models and harnesses, but centralise identity, audit, cost and policy boundaries before fragmentation becomes infrastructure debt.
